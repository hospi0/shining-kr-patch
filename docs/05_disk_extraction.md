# 디스크 스크립트 추출 (2026-07-11)

RAM 스냅샷이 아닌 **디스크 파일**에서 직접 텍스트를 추출하는 파이프라인.

## X2SAMPLE.MES = 공용 시스템/전투/아이템 메시지 (✅ 완전 추출·검증)

- 디스크 크기 53,868B(0xD26C). 런타임 로드 주소 **0x218000** → `file_off = addr − 0x218000`.
- **파일이 자기완결적**: 헤더 포인터가 파일 안을 가리킴.
  - `[+4]` = table1(코드북) = **0x224a50** (파일 오프셋 0xCA50)
  - `[+8]` = table2_flat(블록 포인터 배열) = **0x225250** (오프셋 0xD250)
  - `[+c]` = 0x80000 (디코드 버퍼 크기)
- ⚠️ **런타임 헤더는 값이 다름**: 런타임 table1=0x227844, table2=0x228044 (디스크 대비 **+0x2DF4** 재배치).
  런타임은 씬 로드 시 데이터가 삽입돼 전체가 밀림. **디스크 파일은 자기 헤더로 완결 디코드**되므로 재배치 무시 가능.
- **7개 블록**(table2_flat[0..6]), 총 **1928 레코드**:

| hi | base(디스크) | 레코드 | 역할 |
|----|------|------|------|
| 0 | 0x21f198 | 512 | 제어/짧은 코드 |
| 1 | 0x22014c | 256 | 스탯업 메시지 (XX가 올랐다) |
| 2 | 0x221c30 | 256 | 시스템 안내문 |
| 3 | 0x222860 | 256 | 아이템/번호 |
| 4 | 0x223170 | 256 | 방어구·마법 아이템명 |
| 5 | 0x223e1c | 324 | 아이템명(가타카나 계열) |
| 6 | 0x2246d8 | 68 | 전투 메시지·아이템 획득 |

- **검증**: 디스크 block6가 런타임 forest_block6(state0~3 스크린샷 확정본)과 **레코드 단위 내용 완전 일치**(길이값만 패딩비트 차이). 덤프 대조 `extract/state2/disk_block6.txt` ↔ `forest_block6.txt`.
- 도구: **`tools/extract_disk.py`** (extract_script.py 재사용, base=0x218000). 전체 덤프 `extract/x2sample_script.txt`.

## 스토리 대사(NPC 대화)는 X2SAMPLE.MES에 없음 — 런타임 씬 주입 데이터

- X2SAMPLE.MES 7블록 전부 시스템/전투/아이템/스탯 메시지. 1928레코드는 풀 RPG 스토리엔 너무 적음.

### ✅ forest NPC 대사 = 런타임 스냅샷 0x225ec6+에 있음 (씬 주입, 검증)
- **예전 4스테이트(`대사도중/`)는 아이템팝업이 아니라 진짜 forest NPC 대화였음**(스크린샷 재확인: state1="どおりで・・・オレたちが来た時／お前しか 見あたらなかったわけだ。", state2="隊長たち まさか・・・"). → **대사 known-plaintext 이미 확보**.
- 런타임 디코드 검증: `@0x225ec6`="どおりで…"(state1 일치), `@0x225f07`="…が閉鎖されて だいぶ経つから／色々な魔物も 住みついてるだろうな。" 등. 덤프 `extract/state2/forest_dialogue.txt`(35+ 메시지, 일부 정렬 미조정).
- 구조: block6(item, ~0x225ea3 종료) **바로 뒤**에 붙은 **바이트정렬 연속 메시지**(길이프리픽스 없이 각 메시지가 이전 종료 직후 시작, Δ37/30/42B). 종료 0x0008.
- **⚠️ 디스크 X2SAMPLE.MES엔 없음**(파일이 0x22526c에서 끝, 0x225ec6은 그 너머). **런타임 로드 시 씬 파일(X6MORI 추정)에서 주입됨**(table1 +0x2DF4 재배치의 정체).

### 🔑 디스크 코드북 ≠ 런타임 코드북 (재삽입 전략에 결정적)
- disk block6 rec0 = `08 ab38d62ff29da680`, runtime block6 rec0 = `08 9d891f79aa3e8d80` → **같은 텍스트(`[0d7][0b2][0c4][0b8][0db][0b3]`), 완전히 다른 압축 바이트**. 각자 자기 코드북(disk table1@0x224a50, runtime@0x227844)으로 정확 디코드.
- Huffman에서 같은 텍스트를 다른 비트스트림으로 인코딩 = **다른 트리**. → **런타임 코드북은 로드 시 재구축됨**(씬별 한자 추가 등 적응형 추정).
- **함의**: 코드북이 동적 재구축 → **단순 재압축(a) 불가 확정**. 재삽입은 **(b) 우회훅**(디코더의 16비트 토큰 소비부를 후킹해 한글 토큰 직접 주입)이 유일한 길.
- forest 대사는 디스크에 **무압축 16비트/8비트 글리프 토큰으로도 저장 안 됨**(state1 토큰열 전 파일 검색 음성) → 디스크선 압축 저장.
- **스토리 대사는 별도 오버레이 추정** — 후보:
  - **X6\*.BIN (11개, 지역 이벤트 오버레이)**: MORI=숲, DUN=던전, GRV=묘지, MAN=저택, WTR=수로, HKR/HOKOR=동굴, PS, MADRTW, BOSSES. 로드 0x0604e0ac(코드 영역), 각 10~15KB, 엔트로피 6.2~6.6.
  - **X09.BIN (95KB)**: X0\* 중 유일하게 **LWRAM 0x200064 로드**(X2SAMPLE 영역 0x218000 바로 아래 인접). 헤더가 LWRAM 포인터 디렉터리. 엔트로피 3~5(압축 아님 추정).

### X6MORI 구조 분석 (부분)
- byte0 로드 base=**0x0604e000**. 헤더 4포인터: 0x0604e0ac(엔트리?), 0x0604e010(코드, `2f86 2f96..`=R8~R12 push 프롤로그), 0x0604e470, 0x0604e46c.
- 레이아웃 추정: 코드(0x10~0x460) · 데이터(0x520~0x23a0) · 이벤트 포인터 테이블(0x23a0~0x2c00, `00000005/6/7..` 마커+포인터군) · 이벤트 정의/좌표(0x2c00~, `fff6`=−10 좌표류).
- **공유 코드북 디코드 실패**: X6MORI를 공유 Huffman 코드북으로 (1) 포인터 타겟 디코드 → 쓰레기(토큰 hi바이트 오염), (2) 전 바이트오프셋 바이트정렬 레코드 스캔(idx=0/mask=0x80) → **깔끔한 종료(0x0008) 후보 단 1건**.

### ⚠️ 결론: 스토리 대사는 X2SAMPLE 공유 코드북을 안 씀 (다중 파일 스캔)
바이트정렬 레코드 스캔(공유 코드북, idx=0/mask=0x80, 첫 32KB)의 클린 종료 후보 수:

| 파일 | 크기 | 히트 |
|---|---|---|
| X09.BIN | 95220 | 8 |
| X01.BIN | 37128 | 7 |
| X02.BIN | 84472 | 12 |
| X6MORI.BIN | 11396 | 2 |
| X6DUN1.BIN | 11008 | 3 |
| X6BOSSES.BIN | 13628 | 4 |

전부 위양성 수준(수 건). **이 스캔이 실패한 진짜 이유 = 잘못된 코드북**: 디스크 X2SAMPLE 코드북으로 X6*를 디코드했으나, forest 대사는 **다른(런타임 재구축) 코드북**으로 압축됨(위 🔑절). 공유 코드북 가정 자체가 틀렸음.

## 다음 단계 (스토리 대사 디스크 추출)
forest 대사는 런타임 스냅샷에서 **이미 추출 가능**(known-plaintext 확보됨). 남은 문제는 **디스크에서 전 게임 대사 추출**(스냅샷 없이 스케일).
1. **X6MORI 디스크 포맷 크래킹 (핵심)** — forest 대사 소스가 X6MORI.BIN 안에 압축돼 있음(무압축 저장 아님 확인). X6MORI가 **자체 코드북**을 갖는지 확인: 런타임 codebook(0x227844~subtables)이 X6MORI에서 로드되는지 역추적. X6MORI 안의 table1형 구조(256×8 포인터배열+트리서브테이블) 탐색. 찾으면 X6MORI 자기 코드북으로 자기 대사 디코드 → 11개 지역파일 전부 동일 방식 스케일.
2. **로드 루틴 역공학** — X6* 로드 시 0x218000 영역에 대사+코드북을 주입/재배치하는 코드(1ST.BIN/X02.BIN) 추적. 이게 disk→runtime 매핑의 정답.
3. 보조: 다른 씬 스냅샷 확보(각 지역 대화 도중) → 스냅샷 기반으로라도 텍스트 확보 가능(단 스케일 나쁨).

## 🏛️ 메시지 시스템 아키텍처 (2026-07-11 확정 — 런타임 메시지 컴파일러)

정적+동적 분석으로 전체 구조 규명:

1. **부팅 로드**: 파일로더(1ST.BIN `0x060152DC`, 래퍼 `0x0601529C`→CD 읽기, **압축해제 아님**)가 파일들을 고정 주소에 로드. 디스크립터 테이블 `0x06014540`+. **X2SAMPLE.MES → 0x00218000에 raw 로드**(확정: 디스크립터 `0x06014580`="X2SAMPLE"+`.MES`, R5=0x218000). X09.BIN→0x200000(LWRAM), X02.BIN→0x06065000 등.
   - 디스크 X2SAMPLE.MES 엔트로피: 헤더 2.39 / 중간(코드북) 5.06 / **블록 7.74(=raw Huffman)** → 파일 자체가 최종 inner 형식, 외부 압축 없음.
2. **씬 진입 시 메시지 컴파일러**(핵심): 게임이 X2SAMPLE 데이터를 입력으로 **새 코드북_B + 재인코딩 메시지 + 씬 대사를 X2SAMPLE 끝(0x22526c) 뒤에 생성**하고, 0x218000 헤더의 table1/table2 포인터를 **codebook_B(0x227844)/table2_B(0x228044)로 재지정**.
   - 증거: 런타임 0x224a50(디스크 codebook_A 위치)이 재인코딩 메시지로 **덮여있음**. forest 대사(0x225ec6)·codebook_B(0x227844)·table2_B(0x228044) 전부 디스크 파일 끝 너머 = 컴파일러 산출물. 런타임 메시지영역 어느 바이트도 디스크에 verbatim 없음.
3. **디코더**(X02.BIN `0x0606cbd4`, seek `0x0606cb84`)가 헤더→codebook_B→메시지 소비.

### 코드북_A ≠ 코드북_B (교차 디코드로 확정)
- 두 코드북은 완전히 다른 트리(disk treeA0@0x21e6ac=`037051fa..`, rt@0x21f950=`08e91bc0..`). 교차 디코드 전부 쓰레기. 각자 자기 데이터만 정확 디코드.

### 미해결: 컴파일러의 **씬 대사 입력 소스** (정적 분석 소진)
- forest 대사가 컴파일러 출력(codebook_B)엔 있지만, **입력 소스 형식/위치 미확정**.
- **전 정적 가설 배제 완료**:
  - SJIS 평문: 전 디스크 Track1에서 "隊長"/"魔物" SJIS **0건**.
  - codebook_A 압축: X6MORI/X09/LWRAM 스캔 음성(2~8건 위양성).
  - codebook_B 압축: X6MORI 스캔 음성(8건).
  - 무압축 16/8비트 글리프 토큰: 디스크 전파일·HWRAM·LWRAM 스냅샷 전부 음성.
  - 헤더(0x218004/8) 쓰는 코드: 리터럴 참조 전무(X02는 전부 읽기=디코더/렌더러, X05의 0x218000은 데이터테이블). 컴파일러는 **계산된 base로 헤더 갱신** → 정적 리터럴 앵커 불가.
- **씬 관리 구조 규명**: **X05.BIN = 씬 매니저**. X6* 파일명 테이블 `0x060cc700`(X6WTR01/00/PS101/PS100/MORI/DUN1...), 씬→파일 포인터배열 `0x060cf544`, 씬 로더 `0x060ccc04`(씬ID→테이블검색 0x060ccb98→파일로더 `0x060153bc` 호출). 로드 직후 RTS → **컴파일은 별도 트리거**(X6* 자체 init 0x0604e010/엔트리 0x0604e0ac가 X02 텍스트엔진 [0x06065064]=0x606d9c8 호출; 메시지ID→[0x060792d0]).
- **결론: 정적 분석으로는 도달 불가. 동적 분석 필요.**
  - **권장: 디버깅 에뮬레이터(Mednafen/Kronos/Yabause 디버거)로 0x00218004(헤더 table1 포인터)에 write 워치포인트** → forest 씬 진입 시 컴파일러가 write하는 순간 브레이크 → PC(컴파일러 코드)+레지스터(소스 포인터) 관측 → 대사 입력 소스 즉시 특정. 이후 그 포맷으로 11개 X6* 전부 디스크 추출.
  - 보조: 씬별 스냅샷으로 런타임 버퍼 직접 추출(스케일 나쁨, forest는 이미 됨).

## 재삽입 함의 (확정)
런타임 코드북이 **씬 진입마다 동적 재구축**됨(메시지 컴파일러) → 단순 재압축 불가. **(b) 우회훅**(디코더 16비트 토큰 소비부 후킹, 무압축 한글 토큰 직접 주입)이 유일한 재삽입 경로로 확정.
- 단, **시스템 메시지(X2SAMPLE.MES)는 디스크서 직접 편집 가능**(codebook_A로 재인코딩되는 raw 입력). Korean은 codebook_A에 없으므로 결국 우회훅 필요하지만, 텍스트 위치/구조는 디스크서 완전 파악됨(1928레코드).
