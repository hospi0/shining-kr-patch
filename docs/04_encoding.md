# 텍스트 인코딩 해독 (2026-07-11)

known-plaintext 4장(대사 도중 세이브스테이트, forest 씬)으로 **디코드 버퍼 인코딩 완전 해독**.
원본 스테이트: `my data/state/대사도중/*.state{,1,2,3}` → state0~3.png와 1:1.

## 두 레이어 구조 (확정)

게임은 **소스(압축) → 디코드 버퍼(16비트 글리프 인덱스) → 8bpp 블릿** 파이프라인.

### 레이어 A — 소스 스크립트 (압축, LWRAM)
- 위치: **LWRAM 0x00200000대**(스냅샷 0x225xxx 관측). WRAM은 스냅샷서 swap16 저장.
- **메시지 읽기 포인터 = HWRAM `0x0607bb94`** (텍스트엔진 상태영역). 상태별 값:
  s0=0x00225ec4, s1=0x00225ee9, s2=0x00225f07, s3=0x00225f31 (줄마다 전진, Δ=37/30/42 바이트).
- 데이터 **엔트로피 7.80 bits/byte, 256개 값 전부 등장 → 압축 확정**. 저위 평문 아님.
- 소스 37바이트 → 디코드 38토큰(near 1:1)이지만 바이트값 무관.

### 디컴프레서 = order-1 문맥 Huffman ✅ 역공학+구현+검증 완료 (2026-07-11)
- **런타임 디코더 = HWRAM `0x0606cbd4`** (부바이트 getter). srcptr(0x0607bb94) 읽는 곳, 디코드버퍼 헤더(0x0607b388=마스크) 갱신.
- **알고리즘** (tools/decompress.py에 구현):
  - 상태: `idx` = **직전 출력 바이트(order-1 문맥, 초기 0)**. 입력 비트스트림 `sb`(ptr@0x0607bb94, mask@0x0607b388, MSB-first).
  - 코드북 = `table1 @ [0x218004]`(=0x227844): **256엔트리 × 8B**, `entry[idx]=(symbase_ptr, treeA_ptr)`. 서브테이블은 0x21f8ac~0x21fdxx.
  - `decode_byte(idx)`: symbase,treeA=entry[idx]; sa=treeA 비트리더(mask0x80, 매호출 리셋); R8=0; 루프{ a=sa.bit(); if a==1 return symbase[R8]; b=sb.bit(); if b==0 continue; 카운트섹션(cnt=0; sa 비트로 a2==1이면 R8++,cnt--, 아니면 cnt++; cnt<0까지) }.
  - **16비트 토큰 = decode_byte 2회(hi,lo)**. 압축비 ~2:1(상위바이트 대부분 0x00).
- **디코드 테이블 = LWRAM 0x218xxx** (0x218000 헤더 포인터배열, [0x21800c]=0x80000 크기) — **X2SAMPLE.MES 로드주소(0x218000)와 일치**. Huffman 코드북은 **고정·전 씬 공유**로 추정.
- **검증**: forest 스테이트 4장. 시작 `ptr=0x225ec6,mask=0x80`부터 디코드 → msg1~3이 state1~3 스크린샷과 **바이트 완전일치**(scripts/{huff_decode,decode_all}.py). (스냅샷 저장상태 ptr/mask는 look-ahead로 몇 비트 차이 — 무관.)
### 메시지 프레이밍 ✅ 완전해결 (2026-07-11, tools/extract_script.py)
- **메시지 = 바이트정렬 길이프리픽스 레코드**: `[len:1][압축데이터:len]`. 각 레코드 = 한 텍스트박스, **idx=0 / mask=0x80 리셋**하고 order-1 Huffman 독립 디코드.
- **블록 인덱스**: `table2_flat = [0x218008](=0x228044)`의 4바이트 포인터 배열. `블록베이스 = table2_flat[msgid_hi]`. 관측 스냅샷선 hi=0~6 유효(base 0x220500/2214d0/222f94/223bc4/224510/225228/**225b2c=forest**), 각 224~512 레코드.
- **seek 함수 = HWRAM 0x0606cb84**: idx=0,mask=0x80 리셋 → R3=table2_flat[hi] → msgid_lo개 레코드 스킵(R3+=len+1, 각 len은 선두 1바이트) → **srcptr=R3+1**(선택 레코드 data 시작).
- **종료 토큰**: 0x0008(버튼대기, 최다) / 0x0007 / 0x0006 / 0x0004(대화종료?) 등 박스흐름 제어. 이후 0x0000·공백은 패딩.
- **검증**: block6 rec58~61이 state0~3 스크린샷과 **완전일치**(rec58=state0, 59=state1, 60=state2, 61=state3). rec59 data=0x225ec6 = 브루트포스 msg1 시작과 일치. 덤프 `extract/state2/forest_block6.txt`.
- **미해결4(한자 index→char 전체표)**: 디코드는 완벽하나 한자 인덱스(0x100+) 중 4-스테이트로 못 채운 것은 `[xxx]`로 남음. 폰트 글리프 추출로 전체표 완성 필요(번역엔 문맥으로 대부분 보완 가능).
- **재삽입 함의**: 코드북은 기존 JP 토큰만 커버 → Korean 신규 심볼은 코드가 없음. 따라서 **(b) 우회 훅**(디코더/토큰소비부를 후킹해 무압축 16비트 토큰 직접 주입, 유력) 또는 코드북 확장. 단순 재압축(a)은 불가.

### 레이어 B — 디코드 버퍼 (16비트 인덱스, HWRAM) ✅ 완전 해독
- 위치: **HWRAM `0x0607b390`**부터 16비트 **빅엔디언** 글리프 인덱스 배열(앞 16바이트 `da d5 da d5 00 22 26 a5 XX 16 da d6 da d6 da d6`는 헤더).
- 종료 마커 `0x0008`. 이후는 잔여 버퍼(무시).
- 유성음 = **기본음 + `0x00de`(탁점 ゛)**. 반탁점도 유사 추정(미확인).
- 제어: `0x0020`=공백, `0x0003`=줄바꿈, `0x0008`=종료.
- 검증: 4줄 전부 이 모델로 길이·값 무결(build_table.py conflicts=0).

- **한자**: 0x100+ 인덱스. 0x354부터는 씬 내 **등장순 순차할당**(背355 負356 走357 長358 後359 / 閉35a 鎖35b 々35c 住35d) = **동적 VRAM 글리프 캐시 슬롯**(불안정, 씬 종속). 0x1xx~0x2xx대(間0x1dc 見0x1cd 来0x233 隊0x2bc 등)는 산발적 → 사전 로드 상용한자 고정표일 가능성(미확정).

## 한글패치 함의
- **레이어 B 인코딩은 새 글리프(한글) 삽입에 그대로 활용 가능** — 고정 저위 슬롯에 한글 자모/음절 글리프를 배치하고 인덱스로 참조.
- 단, 실제 편집 대상은 **레이어 A(압축 소스)** → 디컴프레서를 풀어야 재삽입 가능. 또는 디컴프 우회(디코드 버퍼 직접 주입) 훅.
- 한자 동적 캐시는 한글에는 불필요(한글은 고정 슬롯으로 충분할 수 있음). 다만 한글 음절 수(~2350)가 고정 슬롯 범위를 초과하면 동적 캐시 메커니즘 재활용 검토.
